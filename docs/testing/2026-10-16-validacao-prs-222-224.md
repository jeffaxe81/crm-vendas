## Problemas encontrados e corrigidos

A primeira execução dirigida aprovou 300/300. A primeira regressão completa
aprovou 608/610 e reprovou dois testes existentes:

1. `email-provider-preference-panel.test.tsx` — “stages Gmail for one company
   without connecting account or enabling sends”: a mensagem anterior e o novo
   SaveNotice exibiam simultaneamente “Preferência salva”, duplicando a
   confirmação e sua região de status. Foi removida a mensagem redundante,
   preservando no SaveNotice a informação de conta não conectada/envio desativado.
2. `branding-editor.test.tsx` — “previews color edits without saving and submits
   the selected profile”: confirmação nova omitia “para esta empresa” e coexistia
   com a anterior. O sucesso agora usa apenas a confirmação comum, com o contexto
   da empresa preservado. Avisos de rascunho continuam independentes.

Os quatro testes dos dois painéis passaram após a correção. A suíte completa
foi repetida: **610/610 aprovados, sem falhas nem casos pendentes**.
Não foi necessário alterar as expectativas desses testes existentes.

## Comandos executados

A partir de apps/web:

```bash
node node_modules/vitest/vitest.mjs run src/validation src/app/page-pr222-session-12.test.tsx --reporter=json --outputFile=/tmp/crm-300-tests.json
node node_modules/vitest/vitest.mjs run --reporter=json --outputFile=/tmp/crm-web-final.json
```

Na raiz:

```bash
node node_modules/typescript/bin/tsc --noEmit -p apps/web/tsconfig.json
```

O primeiro comando tentado usou um caminho incorreto para o executor e saiu
antes de executar testes; foi corrigido e não foi contado como caso.
Vite emitiu aviso de compatibilidade futura do configLoader native; não houve
falha de execução associada a esse aviso.
